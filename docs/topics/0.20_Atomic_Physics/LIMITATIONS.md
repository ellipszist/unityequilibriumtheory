# Limitations

- The primary verifier uses the standard Rydberg relation with CODATA `R_H`; it does not derive `R_H` from UET first principles.
- The current benchmark covers selected hydrogen Balmer and Lyman lines only. Hydrogen line uncertainty fields are transcription-rounding bounds from the local working copy, not official NIST measurement uncertainties.
- The formula bridge manifest records Bohr/de Broglie/Rydberg inheritance and UET dependency roles, but it is not itself a proof that UET derives the atomic spectrum.
- `0.13` can currently be used only as energy/information accounting context for atomic transitions; it does not derive `h`, `R_H`, or the transition operator in this topic.
- `0.6` and `0.17` can currently be used only as dependency context for `alpha`, charge-sector constants, and electron mass; they do not close the atomic Hamiltonian here.
- Hydrogen level-energy rows support only rounded `n`-level benchmark language. Direct ASD per-level precision, fine-structure splitting, Lamb shift, hyperfine structure, and QED level corrections remain outside this gate.
- Hydrogen-like ion rows now support only a provisional selected He+/Li2+ reduced-mass benchmark plus a C VI higher-Z stress-test lane. The domain-coverage gate records only `Z=2,3,6`, and all current rows are 2 -> 1 Lyman-alpha style targets. Li III still needs direct primary ASD capture, and `5/5` coverage checks block broad hydrogen-like ion validation.
- The selected He+/Li2+ and C VI ion rows use representative source wavelengths/blends; they do not resolve or validate fine-structure/QED components.
- Precision spectroscopy rows for 1S-2S, Lamb shift, and 21 cm hyperfine support source-package targets plus nonrelativistic, leading Dirac, empirical Lamb-handoff 1S-2S residual diagnostics, 21 cm wavelength bookkeeping, and a leading Fermi-contact hyperfine baseline only. No first-principles QED/recoil/proton-radius/hyperfine Hamiltonian residual model is primary-gated yet.
- Neutral helium rows are source-package targets with photon energies, NIST term assignments, wavelength-medium normalization, line-component/blend policy, ground-state baseline residual diagnostics, an external correlated ground-state reference target, excited-state target energies, zero-quantum-defect hydrogenic residuals, a fixed-screening heuristic baseline, limited source-calibrated quantum-defect predictions, same-source-family NIST holdout diagnostics, and restricted same-source-family wavelength predictions computed only. The current predicted holdout lines are below 2000 A and treated as vacuum under the NIST wavelength convention; standard-air holdout lines are skipped until a conversion policy exists. The independent-electron baseline intentionally overbinds, the variational effective-charge baseline remains uncorrelated, and the zero-quantum-defect excited baseline exposes missing singlet/triplet/quantum-defect/correlation structure. The fixed-screening baseline uses `Z_eff = 2 - 0.85` locked before evaluation, has `~0.549 eV` average residual, improves only 2 rows versus zero-QD, and is not a CI/correlated model or UET atomic operator. The quantum-defect prediction gate fits from the same selected source package; its fitted-parameter uncertainty diagnostics use same-series scatter where available and leave-one-out RMSE fallback for the current holdouts. The holdout gates use the same NIST source family, so they are not independent validation; no in-repo correlated two-electron spectral model, independent external holdout package, uncertainty-aware threshold, resolved line-shape policy for precision use, or many-electron residual model is primary-gated yet.
- The predictive-closure gate is a governance contract, not a new validation result. It keeps broad atomic prediction blocked until independent holdouts, comparator baselines, fixed-parameter CI/correlated or UET operators, uncertainty propagation, and a multi-atom benchmark suite exist.
- The predictive-model specification gate defines the required `standard_baseline + delta_uet_or_ci` model contract, but it is not a working model. It records `4` development lanes, `3` blocked lanes, and `4` blocking implementation blockers; no UET correction operator or fixed-parameter generative spectral model is primary-gated yet.
- The first predictive implementation candidate gate selects helium quantum-defect same-source-family holdouts as the narrowest current diagnostic lane. It has `3` level holdout predictions and `2` wavelength holdout predictions, but independent external validation remains blocked and the lane still fits quantum defects rather than deriving them from UET.
- The predictive-v1 parameter-lock gate records the current parameter policy before validation claims. It marks `3` inherited constants as not fitted, records `1` calibrated quantum-defect policy row, and lists `4` forbidden holdout/external leakage fields, but it still has `1` missing future locked parameter: the CI/UET correction operator.
- The predictive-v1 threshold gate records diagnostic thresholds before future validation attempts. Current same-source-family diagnostics pass `3/3` diagnostic thresholds, but `0/3` thresholds are validation-ready because source uncertainty, a non-NIST independent source package, and a fixed correction operator remain missing.
- The predictive-v1 fixed-correction operator gate defines what would count as `delta_uet_or_ci`, but it does not implement it. It records `3` candidates, `0` accepted fixed correction operators, and keeps empirical quantum defects out of the CI/UET operator role.
- The predictive-v1 operator candidate resolution gate explains why available formulas and model lanes are not enough to claim the missing correction operator. It records `7` candidate resolutions, `0` accepted `delta_uet_or_ci` operators, `5` rejected existing candidates, and `2` missing acceptable operator paths.
- The predictive-v1 operator build-spec gate makes the first correction-operator implementation actionable, but it is not the implementation. It records `2` implementation-ready spec lanes, `0` accepted implemented lanes, and keeps validation blocked until an operator emits residual and uncertainty rows.
- The predictive-v1 operator residual gate now exports `3` same-source-family He I diagnostic residual rows with schema/no-leakage fields and populated `delta_energy_eV` values relative to the zero-quantum-defect baseline. These rows are not an accepted CI/UET correction operator, are not independent validation, and keep accepted `delta_uet_or_ci` operator count at `0`.
- The predictive-v1 operator acceptance-harness gate names the concrete module path, parameter manifest, residual rows, uncertainty policy, and residual-row schema needed before an operator can be accepted. Its schema/no-leakage checks now pass on the diagnostic rows, but it still cannot upgrade validation or operator acceptance until a fixed CI/correlated or explicit UET correction operator exists.
- The predictive-v1 diagnostic report is the current implementation report for the selected lane, not a validation result. It records `3` same-source-family level predictions, `2` wavelength predictions, `3/3` diagnostic threshold passes, and `3` validation blockers: missing fixed CI/UET correction operator, non-NIST source package, and validation-ready thresholds.
- The predictive-model blueprint gate answers how to build the next model, but it is not the model. It records `7` build steps with `5` partial steps and keeps the path partial until fixed-parameter CI/correlated or UET correction operator, validation-ready uncertainty thresholds, and a non-NIST independent source package exist.
- The helium external-holdout acquisition gate identifies CHIANTI He I as an external database cross-check candidate with two overlapping current holdout lines, two raw files, and SHA256 hashes, but it is not an independent validation source because the lineage decision classifies it as NIST-dependent cross-check-only.
- The helium external-holdout residual cross-check gate computes small CHIANTI-vs-current deltas for the two overlap rows, but those deltas are cross-check diagnostics only. The display-rounding policy passes 2/2 wavelength deltas and blocks 2/2 upper-energy deltas for source-version reconciliation, so it cannot be used as independent validation.
- The helium external-holdout source-version reconciliation gate keeps the CHIANTI/current upper-energy mismatch separate from wavelength display rounding. It records 2/2 upper-energy rows as source-version-reconciliation-required, so the CHIANTI rows remain source bookkeeping only.
- The helium external-holdout lineage decision gate classifies CHIANTI He I as `CROSSCHECK_ONLY_NOT_INDEPENDENT` because the captured metadata records NIST ASD lineage. This closes the ambiguous lineage-review state but leaves independent validation blocked until a non-NIST source package exists.
- The baseline-comparator gate is internal and diagnostic. It can show residual improvement over named baselines, but it cannot establish independent helium validation or a first-principles atomic model.
- The legacy multi-electron code audit records that existing multi-electron and three-body scripts are smoke/demo code. They do not load source rows, compute line positions, implement CI/correlation, or emit source-backed spectral residuals.
- The uncertainty-readiness gate maps uncertainty gaps, hydrogen transcription-bound diagnostics, and limited fitted quantum-defect uncertainty diagnostics only. It does not make current hydrogen, helium, QED, or hyperfine residuals uncertainty-qualified.
- The residual uncertainty-budget gate computes source-uncertainty ratios where current source packages contain uncertainty values or where the hydrogen/helium line packages declare transcription-rounding bounds. Those bounds are not official NIST measurement uncertainties. The gate does not add complete model uncertainty and does not close QED/hyperfine/correlated-helium corrections.
- The fixed-parameter model-readiness gate maps current model status only. It does not provide the missing CI/correlated helium spectral model or UET atomic operator, and it explicitly excludes legacy smoke/demo scripts from primary evidence.
- The UET atomic-operator readiness gate maps six required derivation/residual artifacts, all still blocking. It does not derive constants, quantized action, Hamiltonians, transition operators, QED/correlation corrections, or UET residual predictions.
- Local spectral rows may be rounded or curated; source-table transcription precision should be audited before public ppm claims.
- Air wavelengths are present in the data but the primary metric uses vacuum wavelengths only.
- The engine has a local rounded `R_H = 1.09677e7 m^-1`; ppm-level claims should use the CODATA working copy instead.
- The three-body script is a coupling smoke test and does not validate atomic three-body physics.
- Fine structure, Lamb shift, hyperfine structure, neutral-helium residual validation beyond source target preparation, and many-electron atoms are outside the current artifact.
- Downstream core topics must inherit these limitations before using `0.20` as atomic evidence.
- Topic-level source-evidence and branch-claim gates now make that boundary explicit: accepted evidence stops at the hydrogen Rydberg benchmark and constant-consistency branch, not full atomic-theory closure.
- The artifact-level `atomic_claim_scope_gate` is the export controller: hydrogen benchmark
  PASS cannot be cited as first-principles Rydberg derivation, QED correction validation,
  Lamb-shift explanation, helium validation, many-electron solution, or full atomic-theory closure.
