# Incubator Workflow Standard

## Purpose
The Incubator workflow is designed to capture, structure, and refine ideas, real-world policies, and applied problem-solving proposals before they possess the rigorous mathematical or computational foundation required to be a formal UET Research Topic.

## Scope
- Ideas relating to macro-systems (e.g., policy, economics, governance).
- Applied infrastructure (e.g., logistics, smart cities, disaster response).
- High-rise buildings, urban living resilience, and geological or terrestrial systems management.

## Directory Structure
All ideas must be placed within `docs/incubator/` categorized by domain:
- `01_policy_and_strategy/`
- `02_urban_resilience_and_geology/`
- `03_logistics_and_infra/`

## Proposal Format
All new proposals MUST use the `docs/incubator/_template_proposal.md` format.
Key required sections:
1. **The Real-world Problem**: Clearly state the non-academic problem.
2. **Proposed Solution & Policy**: State the actionable intervention.
3. **UET Perspective**: Frame the problem in UET terminology (e.g., entropy optimization, equilibrium, data flow).
4. **Future Research Needs**: Identify missing data, simulations, or mathematical models needed to promote the idea.

## Promotion to Formal Topic (Graduation)
An idea is "graduated" to a formal research topic in `docs/topics/` when:
1. The idea transitions from a subjective policy proposal to a testable framework.
2. A mathematical, thermodynamic, or algorithmic model is established.
3. Verification artifacts can be produced.

Once promoted, the file in the incubator should either be moved to the new topic folder or updated with a clear link to the new topic indicating its graduation.
