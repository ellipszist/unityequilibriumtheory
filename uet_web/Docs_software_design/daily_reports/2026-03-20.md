### Agent Architecture (uet_agents)

The agent system uses a **cognitive psychology memory model** with 4 memory types:

1. **Working Memory** (`WorkingMemoryStore`) - current session context
2. **Episodic Memory** (`EpisodicMemoryStore`) - conversation history with metadata
3. **Semantic Memory** (`SemanticMemoryStore`) - persistent knowledge chunks with evidence bundles
4. **Procedural Memory** (`ProceduralMemoryStore`) - task-type procedures

Flow: `ExecutiveRouter` receives a prompt -> classifies task type -> builds evidence bundle from semantic memory -> calculates equilibrium path via `UETSemanticEngine` -> generates response via `UETResponseComposer` -> stores episode.

The `UETSemanticEngine` uses N-gram lattice + token overlap scoring (not external embeddings) for document retrieval. Knowledge state is persisted to `uet_knowledge_state.json`.

### Web Chat API (Multi-Agent RAG)

`uet_web/src/app/api/chat/route.ts` implements a **keyword-based Multi-Agent RAG** system:

- Loads docs from `research_uet/Docs` and `Docs_software_design/platform_specs`
- Classifies query into specialist agents: blockchain, security, economics, governance, physics, social, general
- Searches chunks by keyword overlap
- Synthesizes answer with source citations

## Session 5: LanceDB Fix, Knowledge Ingestion, LLM Switch, Rust Modules (same day)

### LanceDB Vector Schema Fix

The `OmegaSearch` engine was failing with:
```
RuntimeError: Data type is not a vector (FixedSizeListArray), but Float64
```

**Root cause**: Vectors stored as `list<double>` (variable-length) instead of `fixed_size_list<float>[N]` (fixed-length) that LanceDB requires for ANN search.

**Fix**: Created `research_uet/knowledge_base/migrate_lance_schema.py` that:
1. Reads all 5609 rows from old table
2. Builds explicit PyArrow schema with `pa.list_(pa.float32(), N)`
3. Drops old table, creates new with proper vector types
4. Verifies vector search works

Result: `semantic_vec: fixed_size_list<float>[8]`, `uet_vec: fixed_size_list<float>[20]`
